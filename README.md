# BodyTrain 0.3.0

Приложение для дневника тренировок и питания. React 19 + TypeScript + Capacitor 7, iOS 15+. Интерфейс на русском; дневник работает офлайн.

## Возможности

- Тренировки: свои упражнения, вес и повторы, секунды для планки и минуты для кардио, история, повтор прошлой тренировки, три готовых набора упражнений.
- Вес и повторы подставляются из последней тренировки; выполненные подходы учитываются в тоннаже. Нулевые повторы не сохраняются как выполненный подход.
- Таймер отдыха переживает сворачивание и перезапуск; +15 секунд и пропуск отдыха.
- Питание: четыре приёма пищи, дневник по датам, изменение порции, ручной ввод (включая воду с нулём калорий), недавние продукты.
- Локальная таблица продуктов и открытая база [Open Food Facts](https://world.openfoodfacts.org). Онлайн-поиск запускается кнопкой, результаты кэшируются; поиск и штрихкоды ограничены частотой запросов. В вебе запрос идёт через свой сервер (`/api/off/*`), на iPhone — напрямую.
- Штрихкоды: живой сканер на поддерживаемом iPhone, распознавание фото или ввод цифр.
- Фото еды: встроенный классификатор Apple Vision предлагает продукт без ключа и интернета. Граммы пользователь указывает сам; КБЖУ берутся из таблицы средних значений.
- Облачный анализ: Qwen через Groq, бесплатные vision-модели через OpenRouter или Moondream через Cloudflare Workers AI оценивают компоненты и массу. Перед добавлением можно исключить компоненты и исправить граммы. По фото нельзя гарантировать массу, состав и точные КБЖУ.
- Прогресс: 1ПМ, максимальный вес, тоннаж, повторы или время, калории за неделю и изменение веса тела за неделю, календарный месяц и полгода.
- История взвешиваний по датам: добавление прошлых записей, исправление, удаление с отменой. Изменения показаны в кг и процентах; неполная история и отсутствие свежих данных отмечаются явно.
- Цели питания по параметрам профиля или вручную. Расчёт нормы — ориентировочный.
- Экспорт/импорт JSON; импорт проверяет структуру и значения до замены дневника. При ошибке записи приложение сообщает о ней и позволяет повторить сохранение.

## Бесплатное распознавание и ключ

**Ключ не нужен** для тренировок, дневника, Open Food Facts, сканирования и Apple Vision на iPhone.

В «Профиль → Распознавание еды» доступны три сервиса. Дневные лимиты у них разные — ни один не ограничен одним запросом в день:

- **Groq / Qwen 3.8 27B** — ключ в [Groq Console](https://console.groq.com/keys). [Free план](https://console.groq.com/docs/rate-limits) имеет до 1000 запросов/день, 30 запросов/минуту, 8000 токенов/минуту и 200 000 токенов/день; любой из лимитов может остановить запросы раньше. Точные ограничения своего аккаунта смотри в консоли. Поддержка фото и JSON описана в [Vision API](https://console.groq.com/docs/vision).
- **OpenRouter / бесплатные vision-модели** — ключ в [настройках аккаунта](https://openrouter.ai/settings/keys). У моделей с нулевой ценой [20 запросов в минуту и 50 в день](https://openrouter.ai/docs/api-reference/limits); после пополнения счёта от $10 дневной лимит становится 1000. Неудачные запросы тоже расходуют дневной лимит. Конкретная модель не зашита в код: приложение берёт [каталог моделей](https://openrouter.ai/docs/api-reference/list-available-models), оставляет бесплатные с поддержкой изображений и выбирает из знакомых семейств (Qwen-VL, Gemma, Nemotron VL, Llama Vision, Pixtral и другие) — состав бесплатных моделей на OpenRouter регулярно меняется.
- **Cloudflare / Moondream 3.1** — небольшая vision-модель с 2B активных параметров. На [Workers Free](https://developers.cloudflare.com/workers-ai/platform/pricing/) есть 10 000 нейронов в день. В панели Workers AI выбери `Use REST API`, создай токен по шаблону и скопируй **API Token + Account ID**. При ручном создании нужны права `Workers AI — Read` и `Workers AI — Edit` для своего аккаунта. [Инструкция](https://developers.cloudflare.com/workers-ai/get-started/rest-api/).

Google/Gemini удалён из облачного анализа и не возвращён: на бесплатном тарифе Gemini дневная квота Flash-моделей сейчас измеряется десятками запросов и не публикуется в документации. Старые записи питания с источником Gemini продолжают открываться. Старые настройки автоматически переходят на Groq. Старый ключ Google не используется и не подставляется другим сервисам.

Нажми **«Проверить ключ»**: проверка не отправляет фото и не вызывает inference. Groq проверяет авторизацию и наличие Qwen Vision в каталоге; OpenRouter подтверждает ключ, показывает выбранную модель и дневной лимит; Cloudflare проверяет активность токена. У Cloudflare эта проверка не подтверждает права Workers AI или правильность Account ID — они проверяются при выполнении анализа.

Оставайся на бесплатных планах: приложение не определяет, был ли твой аккаунт переведён на платный тариф. Доступность сети и сервиса для конкретного аккаунта требует проверки; замена Google сама по себе не гарантирует отсутствие региональных ограничений.

Ответ 429 разделён по смыслу: ограничение частоты («подожди минуту») и исчерпанная дневная квота («обновится в следующие сутки») показываются разными сообщениями.

Ключи на iPhone хранятся раздельно в Keychain, в веб-версии — локально в браузере; ключи и Cloudflare Account ID не включаются в резервную копию. Ключи не встроены в исходники или IPA. Для общей публичной версии нужен сервер с авторизацией и квотами, если хочешь оплачивать распознавание централизованно.

Фото и уточнение отправляются выбранному сервису **только по кнопке облачного анализа**, после уменьшения фото до JPEG. Дневник, вес тела и профиль в запрос не входят. Фото не загружается на публичный хостинг: оно передаётся в запросе как base64. КБЖУ и масса по фото — оценка, которую нужно проверить перед сохранением. Локальная таблица содержит усреднённые значения; OFF — данные участников, лицензия ODbL. Сохраняй копии перед переустановкой приложения.

### Поиск продуктов из браузера

`search.openfoodfacts.org` не отдаёт заголовок `Access-Control-Allow-Origin`, поэтому обратиться
к открытой базе напрямую из браузера нельзя — в Telegram Mini App поиск падал с «Open Food Facts
не ответил». Сервер BodyTrain проксирует два запроса сам:

- `GET /api/off/search?q=…&page_size=…` — полнотекстовый поиск (search-a-licious);
- `GET /api/off/product/<штрихкод>` — карточка товара по штрихкоду (API v2).

Это не открытый прокси: адрес к OFF собирает сервер, наружу уходят только эти два GET-запроса к
фиксированным хостам, параметры проверяются, частота ограничена 30 запросами в минуту на IP.
Сервер ставит и `User-Agent`, который просит OFF, — браузеру задавать этот заголовок запрещено.
На iOS запросы идут нативно через CapacitorHttp и сервер не задействуют.

## Вес и умная корректировка

Открой **«Прогресс»**. Три карточки показывают разницу между измерениями около начала и конца недели, месяца и полугода. На экране видны реальные даты сравнения; при короткой истории указан неполный период. Допуск к началу периода — 2, 5 и 14 дней соответственно. График учитывает расстояние между датами, а не число записей. Будущие взвешивания добавить нельзя.

Блок **«Умная корректировка»** оценивает последние 28 дней: минимум 6 записей, минимум 14 дней между первой и последней, по 3 записи в каждой половине периода, последний вес не старше недели. Медиана наклонов пар измерений с интервалом от недели сглаживает отдельные скачки. При сильном шуме или ошибке последнего измерения приложение ждёт новых данных.

Ориентиры — эвристика приложения: похудение 0,25–0,75% массы в неделю (не более 0,75 кг), набор 0,1–0,25%, поддержание в пределах ±0,15%. Эти диапазоны не являются персональным медицинским назначением. Общий принцип постепенного снижения веса описан у [CDC](https://www.cdc.gov/healthy-weight-growth/losing-weight/index.html); точный перевод килограммов в калории не используется: [NIDDK](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner) учитывает динамику изменения массы, активности и обмена.

При отклонении от цели приложение предлагает шаг до 5% нормы, максимум 150 ккал, округлённый по 25 ккал. Перед применением показаны новые КБЖУ. Поправка меняет углеводы, белки и жиры остаются расчётными. Суммарная поправка ограничена 20% формулы и 600 ккал; нижний предел внутри этой функции — 1500 ккал для мужчин и 1200 для женщин, а также энергия расчётных белков и жиров. Эти пределы не гарантируют подходящую индивидуальную норму.

**«Применить»** сохраняет поправку и сразу меняет цели в питании и профиле. Следующая оценка использует только взвешивания после изменения и возможна не раньше чем через 14 дней. Кнопка возврата убирает поправку. Смена цели, активности или параметров профиля начинает новое наблюдение; обычное добавление взвешивания его не сбрасывает. Ручные КБЖУ не изменяются. При возрасте до 18 лет, ИМТ ниже 18,5 или чрезмерно быстром тренде подсказка изменения калорий недоступна.

Корректировка работает полностью **офлайн и без ключа**. Она не определяет фактическую полноту дневника питания: перед изменением нормы нужно проверить, что еда записана полностью и текущая норма соблюдается. Взвешивания и применённая поправка включаются в резервную копию; копии старых версий остаются читаемыми.

## Аккаунты, Telegram Mini App и рейтинг

Без входа всё работает как раньше — дневник только на устройстве. После входа дневник синхронизируется с сервером (`server/`), а тренировки попадают в **рейтинг по тоннажу за сегодня и за неделю**.

- **Вход:** в Telegram — автоматически, по подписи `initData` от бота. В iOS и браузере — логин и пароль. Telegram-аккаунту можно задать пароль («Профиль → Пароль для входа с iPhone»), тогда в iOS-приложении будет тот же дневник. Восстановления пароля по почте нет.
- **Синхронизация:** изменения уходят на сервер через 2 с. Если дневник правили на двух устройствах, работает трёхстороннее слияние (`src/lib/merge.ts`): записи с обеих сторон сохраняются, удаление не «воскресает». При правке одной и той же записи на двух устройствах побеждает текущее устройство. При первом входе гостевой дневник переносится в аккаунт.
- **Рейтинг:** тоннаж считает сервер по синхронизированным тренировкам — выполненные подходы, вес × повторы. Кардио и упражнения на время не входят. Подходы тяжелее 500 кг или больше 100 повторов в рейтинг не идут, одна тренировка ограничена 60 т. «День» и «неделя с понедельника» считаются по `LEADERBOARD_TZ` (по умолчанию Москва). Скрыть себя из рейтинга можно в профиле.
- **Удаление аккаунта** удаляет с сервера аккаунт, дневник и место в рейтинге. App Store требует такую функцию, если в приложении есть регистрация.

### Локально

```bash
createdb bodytrain                       # PostgreSQL 14+
cp .env.example .env                     # для разработки хватит DATABASE_URL
npm run server:dev                       # API на :8787 (миграции применяются сами)
npm run dev                              # фронт, /api проксируется на :8787
npm run test:server                      # тесты API (нужна база bodytrain_test)
npm run tg:link -- 12345 "Иван"          # ссылка «как из Telegram» с подписанным initData
```

### Запуск в Telegram

1. В [@BotFather](https://t.me/BotFather): `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. Задеплой сервер на HTTPS-домен — Telegram открывает Mini App только по HTTPS. Варианты:
   - `docker compose up -d --build` за nginx/Caddy;
   - Railway или Render с PostgreSQL: `npm ci && npm run build && npm run server:build`, затем `npm run server:start` с `NODE_ENV=production`.

   Обязательные переменные: `DATABASE_URL`, `JWT_SECRET` (`openssl rand -hex 32`), `TELEGRAM_BOT_TOKEN`, `PUBLIC_URL`, `TRUST_PROXY=1`.
3. `npm run tg:setup` — ставит боту кнопку меню «Открыть», описание и webhook для ответа на `/start`. Для webhook нужен `TELEGRAM_WEBHOOK_SECRET`.
4. Чтобы приложение открывалось из профиля бота: в BotFather `/mybots → Bot Settings → Configure Mini App`, URL — тот же `PUBLIC_URL`.

### iOS с аккаунтом

Адрес сервера вшивается при сборке:

```bash
VITE_API_URL=https://bodytrain.example.com npm run ios:ipa
VITE_API_URL=http://localhost:8787 npm run ios:sim     # симулятор + локальный сервер
```

Без `VITE_API_URL` iOS-сборка работает офлайн: блок аккаунта скрыт, рейтинг показывает «сервер не настроен». Токен сессии на iPhone хранится в Keychain.

## Запуск и сборка

```bash
npm ci
npm run server:dev       # API на :8787 — нужен и для поиска в Open Food Facts
npm run dev              # http://localhost:5173
npm test                 # расчёты, store, импорт, AI, OFF, сохранение
npm run test:server      # API и прокси к OFF (нужен PostgreSQL)
npm run build            # проверка TypeScript и production web
npm run ios:sim          # сборка и запуск на iPhone 17 Pro Simulator
npm run ios:sim -- "iPhone SE (3rd generation)"
npm run cap:open         # Xcode
npm run ios:ipa          # build/ipa/BodyTrain-unsigned.ipa
```

Нужны macOS, Xcode и CocoaPods. Сборка без подписи проверяет компиляцию для реального iPhone, но IPA надо подписать для установки (например, своим Apple ID через инструмент установки). Для подписи в Xcode выбери свою Team в Signing & Capabilities. App Store/TestFlight требуют соответствующей учётной записи и настройки распространения.

```bash
TEAM_ID=XXXXXXXXXX npm run ios:ipa
bash scripts/selftest-sim.sh
```

Нативный самотест использует **отдельный bundle ID** `com.voodeex.bodytrain.selftest`: не меняет основной дневник. Проверяет реальные запросы OFF, Keychain, Vision-сканер, запись JSON и восстановление store. Apple Vision классификацию пропускает в симуляторе — для неё нужен физический iPhone. После самотеста обычная сборка восстанавливается командой `npm run cap:sync` или `npm run ios:sim`.

`npm run ios:ipa` по умолчанию сохраняет артефакт в проекте; другой путь задаётся `OUT_DIR=/absolute/path`. Скрипт подписанного экспорта зависит от доступного provisioning profile; для Personal Team удобнее установка из Xcode.

## Структура

- `src/screens`, `src/components` — интерфейс.
- `src/store/app.ts` — дневник и действия.
- `src/lib/validation.ts` — проверка резервных копий и внешних данных.
- `src/lib/weightTrend.ts`, `nutrition.ts` — периоды, устойчивый тренд и поправка КБЖУ.
- `src/lib/foodAI.ts`, `openFoodFacts.ts`, `bodyVision.ts` — распознавание и источники.
- `ios/App/App/BodyVisionPlugin.swift` — Vision, сканер и Keychain.
- `ios/App/App/PrivacyInfo.xcprivacy` — декларации iOS.
- `scripts/ios-native-setup.rb` — повторяемая донастройка Xcode после создания платформы.
- `server/src` — API (Hono + PostgreSQL): `app.ts` — маршруты, `auth.ts` — пароли, JWT и проверка `initData`, `stats.ts` — тоннаж для рейтинга, `db.ts` — миграции.
- `src/store/account.ts` — вход и синхронизация, `src/lib/merge.ts` — слияние дневников, `src/lib/telegram.ts` — Telegram SDK, `src/screens/Leaderboard.tsx` — рейтинг.
- `Dockerfile`, `docker-compose.yml`, `.env.example` — деплой.

Без действующих личных ключей живой inference Groq/OpenRouter/Cloudflare не проверяется. Лимиты бесплатных тарифов меняются провайдерами — числа в этом разделе нужно сверять с их документацией. Установка и классификация реальной еды на физическом iPhone — отдельная проверка от успешной сборки и тестов в симуляторе.
